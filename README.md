# Avito CRM

CRM с мультипользовательским доступом и подключением нескольких аккаунтов Авито
в единую систему: заявки/сообщения со всех аккаунтов попадают в общий инбокс,
воронку продаж и карточки клиентов, а ответы из CRM уходят обратно в Авито.

## Что уже реализовано

- Мультитенантность: компания (workspace), несколько пользователей, роли и права доступа
- Подключение **любого количества** аккаунтов Авито (каждый со своим client_id/secret)
- Единый вебхук `/webhooks/avito` — сообщения со всех аккаунтов попадают в общий список чатов
- Карточка чата: метка аккаунта-источника, статус прочитано/не прочитано, закреплённый менеджер,
  привязка к контакту в базе
- Ответ клиенту прямо из CRM → отправка в Авито через API
- Воронка продаж с настраиваемыми (добавить/удалить/переименовать/переставить) этапами
- Сделки: товары, сумма, статус (в работе/успех/отказ)
- Шаблоны быстрых ответов
- Клиентская база (контакты) с ролевым доступом, импорт/экспорт CSV
- Товары/услуги, выставление счетов со статусами оплаты
- Задачи: приоритет, дедлайн, напоминание, исполнитель; эндпоинт уведомлений для опроса с фронта
- Базовый каркас складского/производственного учёта: материалы, остатки, себестоимость,
  затраты на доставку, расчёт себестоимости товара по норме расхода

## Что осталось доработать под ваши задачи (не входит в этот MVP)

- PDF-генерация счетов (сейчас счета — это данные в БД + UI, печатной формы PDF нет)
- Полноценный производственный учёт (планирование бюджета, партии производства, спецификации BOM
  на уровне UI — модель данных для этого уже есть: `Material`, `MaterialUsage`)
- Push/email-уведомления (сейчас — polling-эндпоинт `/notifications`, на него можно повесить
  веб-пуши или Telegram-бота для реальных уведомлений)
- Другие мессенджеры (VK, Instagram, WhatsApp, MAX) — архитектура каналов (`ChannelType` в схеме
  БД) сделана так, чтобы добавить их по аналогии с `services/avitoClient.ts`, но сами интеграции
  не реализованы
- Автоматизация задач по триггерам (например, "создать задачу при переходе сделки на этап X") —
  модели готовы, движок правил не написан

## Технологии

- Backend: Node.js, TypeScript, Express, Prisma ORM, PostgreSQL, JWT-авторизация
- Frontend: React, TypeScript, Vite, Tailwind CSS, react-router

## Установка (локально)

### 1. База данных

Быстрый способ — Docker:

```bash
docker compose up -d
```

Либо укажите свой PostgreSQL в `backend/.env` → `DATABASE_URL`.

### 2. Backend

```bash
cd backend
npm install
npx prisma migrate dev --name init
npm run dev
```

Backend поднимется на `http://localhost:4000`.

Ваши ключи первого аккаунта Авито уже лежат в `backend/.env`
(`AVITO_SEED_CLIENT_ID` / `AVITO_SEED_CLIENT_SECRET`) — они не используются автоматически,
это просто чтобы не потерять их. Сам аккаунт подключается через интерфейс:
**Настройки → Аккаунты Авито → Подключить аккаунт** (после регистрации в CRM).

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`, зарегистрируйте компанию (это создаст первого
пользователя с ролью «Владелец» и базовую воронку с 5 этапами).

### 4. Подключение аккаунта Авито

1. Получите `client_id` и `client_secret` в личном кабинете разработчика на
   https://developers.avito.ru (это делается один раз на аккаунт Авито).
2. В CRM: **Настройки → Аккаунты Авито → Подключить аккаунт**, укажите название,
   client_id, client_secret.
3. CRM автоматически получит `access_token` и `avito user_id`, а также попытается
   зарегистрировать вебхук — но это сработает **только если backend доступен из
   интернета по HTTPS** (см. ниже).
4. Повторите шаг для каждого следующего аккаунта Авито — их можно подключить сколько угодно.

## Деплой (важно для получения сообщений)

Авито шлёт вебхуки на ваш сервер только по **публичному HTTPS-адресу**. На локальной
машине (`localhost`) это не сработает. Для продакшена:

1. Разверните `backend` на сервере (VPS, Render, Railway, Fly.io — на ваш выбор) с
   доменом и HTTPS-сертификатом.
2. Разверните `frontend` (можно как статику на том же сервере через nginx, либо на
   Vercel/Netlify, указав в `vite.config.ts` прокси на реальный домен backend).
3. Пропишите в `backend/.env` → `PUBLIC_BASE_URL` реальный адрес, например
   `https://crm.mycompany.ru`.
4. Пересоздайте/повторно подключите аккаунты Авито через UI («Повторить подключение») —
   это зарегистрирует вебхук на правильный публичный URL.
5. Выполните `npx prisma migrate deploy` на проде вместо `migrate dev`.

## Структура проекта

```
backend/
  prisma/schema.prisma   - вся модель данных (см. комментарии по секциям)
  src/routes/            - REST API по модулям (auth, avitoAccounts, chats, deals, ...)
  src/services/avitoClient.ts - вся интеграция с Avito API (токены, отправка, вебхук)
  src/routes/webhooksAvito.ts - приём сообщений от Авито (единая точка входа)
frontend/
  src/pages/             - экраны CRM
  src/pages/settings/    - настройки (аккаунты Авито, воронка, шаблоны, пользователи)
```

## Безопасность

`backend/.env` содержит реальные секреты — не публикуйте его и не коммитьте в
публичный git-репозиторий (файл уже добавлен в `.gitignore`). Поскольку
client_secret вашего первого аккаунта был передан в чате, рекомендуется после
тестового запуска перевыпустить его в личном кабинете developers.avito.ru.
